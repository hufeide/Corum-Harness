## Q1 二级页面布局 — ✅ 三方一致：左右分栏

- **左栏 320px 固定**：返回按钮（顶部）+ 名片预览（sticky，实时同步编辑）+ 底部删除按钮（与保存物理隔离）
- **右栏 flex:1 独立滚动**：表单分组按「基础信息 → 继承自 → 提示词 → 技能绑定 → MCP 绑定 → 终端/记忆」顺序
- 窄屏 <1280px 降级为上下结构（名片吸顶）
- 名片预览实时反映草稿状态（所见即所得）

## Q2 「继承自」标签 — 以用户原话定稿

**用户原话**：「选择官方 Agent 模式，改为继承自。这个后续展示在名片上，加个标签展示。」

- **名片上显示**：模型行右侧加「继承自 standard」标签（ghost chip 弱样式，$glass-2 + 12px $label-secondary，与信任级徽标一虚一实区分）
- **表单中**：字段名改为「继承自」，下拉选项保留完整描述
- 前端架构师补充：仅 baseMode !== 'standard' 时渲染（standard 是默认无信号价值）——**暂不采纳**，用户要求「加个标签展示」，先全部显示，后续可按反馈调整
- 产品经理建议「主页名片不显示」——**与用户原话冲突**，用户明确要「展示在名片上」，故显示

## Q3 提示词放大 — 占满右栏 overlay

- 提示词组标题行右侧「放大」按钮（Maximize2 图标）
- 点击进入**放大态**：占满右栏内容区（保留左栏名片预览可见，实时看首行变化反映到「擅长什么」）
- 放大态顶部工具栏：左侧「← 返回编辑」，中间「提示词」，右侧「AI 润色」+「缩小」（Minimize2）
- **手动缩小**（不自动缩小）：用户点击「缩小」或 Esc 返回表单
- **AI 润色**：在放大态内联进行（底部展开润色面板），支持「接受/拒绝/重新生成」，接受后替换 textarea 内容
- **保存后行为**：保存按钮在编辑页 footer（不在放大态），放大态只管编辑内容
- **红线**：AI 润色按钮要么做真的（调 LLM API），要么暂时隐藏，不留 disabled 占位

## Q4 完整状态链路 — edit 内部 overlay 模式

**View union**（顶层）：
```ts
type View =
  | { kind: 'home' }                                    // 名片主页
  | { kind: 'edit'; profile: AgentProfileSummary | 'new' }  // 二级编辑页（左右分栏）
```

放大态、技能/MCP 绑定弹窗、删除确认弹窗都是 `edit` 内部的 overlay/dialog 状态，不进 view union。

**跳转矩阵**：
- `home → edit`（点击卡片 chevron / + 新建预设）
- `edit → 放大态`（提示词组放大按钮，edit 内部 state）
- `edit → 技能绑定弹窗`（dialog overlay，onClose 回 edit）
- `edit → MCP 绑定弹窗`（dialog overlay，onClose 回 edit）
- `edit → 删除确认弹窗`（dialog overlay，确认后回 home + reload）
- `edit.onSaved → home + reload`（保存成功）
- `edit.onBack → home`（有未保存修改时弹确认弹窗；无修改直接返回）

**关键边界**：
- 保存校验失败：表单内联报错，不跳转
- 删除被引用 Agent：后端返回错误，前端展示错误提示
- 新建预设：复用 edit view，字段为空/默认值，名片预览显示占位态，ID 可编辑，无删除按钮
- 返回有未保存修改：弹确认弹窗；无修改直接返回
- 弹窗 z-index：二级编辑页 < 技能/MCP 绑定 < 提示词放大态 < 删除确认 < toast
