# Agent 预设页交互设计 · 最终建议

> 针对 Q1（二级页面布局）、Q2（继承自标签）、Q3（提示词放大）、Q4（完整状态链路）的 UX 定稿意见。
> 约束：液态玻璃 token 体系 / Lucide 图标 / 深浅双主题 / 不改官方内核。

---

## 设计总原则

1. **身份在左，能力在右**：名片是「我是谁」，表单是「我能做什么」，两者分区而非混杂。
2. **所见即所得**：任何编辑动作应实时反映到名片预览，消除「保存后才知道效果」的往返。
3. **显式优于隐式**：继承关系、继承来源等决策性信息直接展示，不藏在 hover/tooltip 里。
4. **用户掌控节奏**：模态的进入/退出由用户主动触发，不做「自动收起」类的代客操作。

## Q1 二级页面布局

### 方案对比

| 方案 | 结构 | 优势 | 劣势 |
|------|------|------|------|
| A. 上下结构（现状） | 返回行 + 右上 248px 名片 + 下方全宽表单 | 实现简单；名片常驻视口 | **左侧全部空着**（用户已指出）；动线呈 Z 字形；名片与表单上下文割裂 |
| **B. 左右分栏（推荐）** | 左 320px 固定名片栏 + 右侧弹性表单区 | 左→右 F 型动线；实时预览即所见即所得；空间利用率高 | 窄屏需响应式降级；左栏长内容需独立滚动 |
| C. 顶部通栏 + 双列表单 | 顶部 120px 横向名片 + 表单两列 | 名片突出；表单视觉平衡 | 纵向空间消耗大；名片横拉后信息密度低；字段多时双列拥挤 |

### ✅ 推荐：方案 B（左右分栏）

```
┌────────────────────────────────────────────────┐
│ ← 返回   编辑预设                    [保存]     │
├──────────────┬─────────────────────────────────┤
│              │  ① 基础信息（昵称/岗位/经验/头像）│
│   名片预览    │  ② 继承自（baseMode 选择）       │
│  （实时同步）  │  ③ 提示词            [⤢ 放大]  │
│   320px      │  ④ 技能绑定                      │
│   独立滚动    │  ⑤ MCP 绑定                      │
│              │  ⑥ 危险操作（删除）              │
└──────────────┴─────────────────────────────────┘
```

**推荐理由**：
- **信息层级**：左栏 = 身份锚点（用户始终知道在编辑谁），右栏 = 能力配置，形成「身份 → 能力」的递进。
- **视觉动线**：F 型阅读习惯，先看后改，视线无需折返。
- **操作效率**：编辑时名片实时更新，零往返验证。

**表单分组顺序**（按决策依赖排序）：基础信息 → 继承自 → 提示词 → 技能绑定 → MCP 绑定 → 危险操作。继承自前置，因为 baseMode 决定了提示词/能力的默认值来源。

**响应式兜底**：视口 < 1280px 时降级为上下结构（名片吸顶），保证可用性。

## Q2 「继承自」标签

### 方案对比

| 方案 | 位置/样式 | 优势 | 劣势 |
|------|----------|------|------|
| **A. 独立标签（推荐）** | 与岗位维度 chip 同行（左继承右岗位），`GitBranch` 图标 + 「继承自 standard」 | 语义独立清晰；同行放置**不增加纵向高度**；图标降低文字密度 | 图标有轻微学习成本 |
| B. 合并进信任级徽标 | 「系统 · standard」组合标签 | 省一行空间 | **语义混淆**：信任级（谁创建）与继承（从哪派生）是两个维度；「用户 · standard」读起来像系统预设 |
| C. hover 展开 | 默认仅图标，hover 出 tooltip | 零空间占用 | 可发现性差；继承关系是**决策信息**，不该隐藏 |

### ✅ 推荐：方案 A（独立标签，与 chip 同行）

**推荐理由**：
- **信息层级**：「继承自哪个 baseMode」是用户创建/理解预设的核心决策依据，值得显式展示而非隐藏。
- **拥挤问题的解决**：不是「再加一行」，而是**复用 chip 行**——左侧放「继承自 standard」，右侧放岗位维度 chip，横向排列不增加名片高度。
- **语义区分**：信任级徽标回答「谁创建的」，继承标签回答「从哪里派生的」，分开呈现不混淆。

**样式规格**：

| 项 | 规格 |
|----|------|
| 图标 | Lucide `GitBranch`，14px |
| 文案 | `继承自 ${baseMode}`，12px，色 `$label-secondary` |
| 容器 | 背景 `$glass-1`，边框 `$glass-border`，圆角同 chip |
| 与信任级徽标的区分 | 信任级用 `$brand-primary` 实色底；继承自用透明玻璃底——一实一虚，一眼可辨 |

## Q3 提示词放大编辑

### 方案对比

| 方案 | 交互 | 优势 | 劣势 |
|------|------|------|------|
| **A. 全屏模态（推荐）** | 点击放大 → 占满右侧内容区，顶部工具栏（返回 / AI 润色 / 完成） | 沉浸式编辑；AI 润色有空间放对比/确认区；用户掌控节奏 | 模态切换有轻微跳转感 |
| B. 内联展开 | textarea 原地撑高，推挤下方表单 | 无跳转，上下文连续 | 页面抖动；超长提示词仍需滚动；润色预览空间不足 |
| C. 侧边滑出面板 | 右侧滑出 480px 面板 | 左表单仍可参考 | 宽度仍受限；动效复杂；不满足「占满右侧」的原话需求 |

### ✅ 推荐：方案 A（全屏模态 + 手动缩小）

**推荐理由**：
- 提示词是 Agent 预设的**核心内容**（通常数百字），需要无干扰编辑环境。
- AI 润色需要展示「原文 vs 润色后」并提供「接受/拒绝/重新生成」操作区，只有全屏态有充足空间。
- **手动缩小而非自动缩小**：避免「AI 润色完我还没看完就被弹回去」的失控感——节奏交给用户。

**交互细节定稿**：

| 问题 | 定稿 |
|------|------|
| 保存后自动缩小？ | **否**。用户点击「完成」才返回表单 |
| AI 润色在放大态的行为 | 点击「AI 润色」→ 底部展开润色面板（建议文案 + 接受/拒绝/重新生成）→ 接受后替换 textarea，可继续二次编辑 |
| 放大态工具栏 | 左：`← 返回编辑`；中：`提示词`；右：`✦ AI 润色`（Sparkles）+ `完成` |
| 快捷键 | `Esc` 返回表单；`Cmd/Ctrl + Enter` 完成 |
| 进入动画 | 内容区内 fade + scale(0.98→1)，200ms，符合玻璃质感 |

## Q4 完整状态链路

### 方案对比

| 方案 | 形式 | 优势 | 劣势 |
|------|------|------|------|
| **A. 线性流程图 + 异常表（推荐）** | 主页为根节点的分支图，关键节点配异常分支表 | 直观展示入口/出口；易发现断链；规模匹配 | 状态很多时图会变大（本场景 ~8 态，可控） |
| B. 状态机表格 | 「当前态→动作→目标态→副作用」四列表 | 精确无歧义，便于开发对照 | 可读性差，不直观 |
| C. 泳道图 | 用户操作/界面状态/数据变更三泳道 | 区分用户与系统视角 | 绘制成本高；本链路规模下冗余 |

### ✅ 推荐：方案 A

```
                        ┌──────────────────────────────────────────┐
                        │                                          │
┌─────────────┐         │                                          │
│  名片主页    │◄────────┼──────────────[保存成功/删除成功/放弃]──────┤
│  3 列网格    │         │                                          │
└──────┬──────┘         │                                          │
       │                │                                          │
       ├─ 点击卡片 chevron                                           │
       ├─ + 新建预设 ────┐                                           │
       ├─ 筛选 / 搜索（主页内状态，不跳转）                            │
       └─ 官方只读组 → 详情查看（只读，无编辑）                        │
       │                │                                           │
       ▼                ▼                                           │
  ┌────────────────────────────────────┐                           │
  │         二级编辑页                  │                           │
  │      （左名片预览 / 右表单）         │                           │
  │                                    │                           │
  │  ① 基础信息（内联编辑，无子状态）     │                           │
  │  ② 继承自 baseMode（下拉/分段选择）   │                           │
  │  ③ 提示词 ──► 【放大态】            │                           │
  │                ├─ AI 润色 ──► 润色面板（接受/拒绝/重生成）          │
  │                └─ 完成/Esc ──► 回编辑页                           │
  │  ④ 技能绑定 ──► 【技能选择弹窗】──► 确认/取消 ──► 回编辑页         │
  │  ⑤ MCP 绑定 ──► 【MCP 选择弹窗】──► 确认/取消 ──► 回编辑页        │
  │  ⑥ 删除 ──► 【删除确认弹窗】──► 确认 ──► 回主页 ──────────────────┤
  │                                    │                           │
  │  [保存] ──► 校验 ──► 成功 ──► 回主页 ────────────────────────────┤
  │  [返回] ──► 有未保存修改? ──► 【放弃确认弹窗】                     │
  │                  ├─ 确认放弃 ──► 回主页 ──────────────────────────┤
  │                  └─ 取消 ──► 留在编辑页                            │
  └────────────────────────────────────┘
```

### 关键节点异常分支

| 节点 | 异常/边界 | 处理 |
|------|----------|------|
| 保存 | 校验失败（昵称空、提示词空） | 表单内联报错 + 错误字段高亮 + 滚动定位到首个错误，**不跳转** |
| 保存 | 新建预设保存成功 | 回主页，新卡片以进入动画（fade + rise）出现在网格首位 |
| 删除确认 | 预设被 N 个 Agent 引用 | 弹窗警示「正被 N 个 Agent 使用，删除后回退到 standard」，按钮为「强制删除 / 取消」 |
| 新建预设 | 入口 | 复用编辑页，字段为空/默认值；名片预览显示占位态（虚线头像 + 「新建预设」） |
| 返回 | 有未保存修改 | 二次确认弹窗；无修改则直接返回（**无打扰原则**） |
| 放大态 | 返回时提示词未保存 | 提示词属表单字段，返回即保留在表单草稿中，不单独弹确认（与整体「返回时统一确认」策略一致） |

## 附：设计规范速查

| 项 | 规格 |
|----|------|
| 容器层级 | 页面 `$glass-1` → 卡片 `$glass-2` → 弹窗 `$glass-3`，逐层递进 |
| 边框 | 默认 `$glass-border`；聚焦/激活 `$glass-border-active` |
| 主按钮 | `$brand-primary` 底 + `$brand-text` 字；次按钮玻璃底 |
| 图标 | 全部 Lucide：ChevronLeft / Maximize2（放大）/ Minimize2 / Sparkles（AI 润色）/ GitBranch（继承）/ Plus / Trash2 / Search / Ghost（占位卡） |
| 双主题 | 深浅两套 token 自动切换，不做硬编码色值 |
| 弹窗统一行为 | 遮罩点击 = 取消（删除确认除外，防误触）；`Esc` = 取消；确认按钮在右侧 |

## 结论一览

| 问题 | 最终方案 | 一句话理由 |
|------|---------|-----------|
| Q1 | **左右分栏**：左 320px 名片预览 + 右弹性表单，<1280px 降级上下 | 消灭左侧留白，F 型动线 + 所见即所得 |
| Q2 | **独立继承标签**，与岗位 chip 同行，GitBranch 图标 + 玻璃底 | 决策信息显式化，复用 chip 行不增高度 |
| Q3 | **全屏模态放大**，手动缩小，AI 润色内嵌润色面板 | 沉浸编辑 + 润色对比空间 + 用户掌控节奏 |
| Q4 | **线性流程图 + 异常分支表**，8 个核心状态全覆盖 | 规模匹配、入口出口清晰、边界情况有据可依 |
