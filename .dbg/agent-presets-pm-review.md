# Agent 预设页交互设计 — 产品评审意见

> 评审人：资深产品经理视角
> 依据：`/.dbg/agent-presets-requirements.md`（Q1–Q4）+ 现状代码 `SettingsSections.tsx`
> 核心隐喻：**「职场名片」** —— 把 Agent 当成一个「人」来认识、信任、委派

---

## 一、核心判断：信息优先级（贯穿四个问题）

一张「职场名片」在真实世界的信息优先级是：

1. **TA 是谁**（头像 + 昵称 + 岗位）—— 1 秒识别
2. **TA 擅长什么**（一句话简介）—— 决定我是否要继续看下去
3. **TA 凭什么值得信任**（信任级徽标 / 经验履历 / 师承）—— 建立「敢不敢用」
4. **TA 的硬实力**（模型 / 技能 / MCP / 终端）—— 决定「能不能用」
5. **TA 的脾气**（提示词 / 基础模式 persona）—— 决定「合不合得来」

这个顺序，**就是二级页面的视觉与表单顺序**，也是主页名片卡片的信息密度排序。

而「**继承自**」这个标签（Q2），本质上对应职场名片上的「**师承 / 出身**」—— 类似名校毕业、大厂背景、某个老师傅带出来的。它属于**信任层信息**，不应该抢过「岗位」和「擅长什么」的戏。

## 二、Q1 二级页面布局

### 现状问题
当前是「返回行 + 右上 248px 名片预览 + 下方全宽表单」，用户反馈「名片预览左侧全部空着」不合理。这个反馈是对的，且根因是：**预览和表单的关系没有被「产品逻辑」撑起来**。

### 建议方案：**左预览 / 右表单 双栏**

```
┌───────────────────────────────────────────────────────────┐
│ ← 返回        编辑 Agent 预设              [删除] [保存]   │  ← 顶部工具条（固定）
├──────────────────┬────────────────────────────────────────┤
│                  │  ① 基本信息（昵称/岗位/维度/头像）       │
│   名片预览        │  ② 一句话简介（自动 + 可编辑履历）       │
│   （sticky）      │  ③ 提示词（继承自 + 自定义 + 放大）      │
│   320px 宽        │  ④ 模型（主 + 子）                      │
│                  │  ⑤ 技能 + MCP                           │
│   [实时联动]      │  ⑥ 终端 + 记忆                          │
│                  │  ⑦ 信任级 + 危险区                       │
└──────────────────┴────────────────────────────────────────┘
```

### 为什么这样排

- **左侧 320px sticky 名片预览**：用户改任何字段（昵称 / 岗位 / 维度 / 继承自 / 提示词首行），预览**实时联动**。这就是「我在捏一个人」的具身感。左侧空着的问题也顺势解决——预览卡本身就是「左栏内容」。
- **右侧表单按名片优先级降序**：先填「是谁 → 擅长什么 → 脾气 → 能力 → 资源 → 兜底」。新手从上到下不会迷路，老手可以 CMD+F 直达。
- **删除按钮**挪到顶部工具条右侧（红色描边小按钮，不抢眼但常驻），不要塞在表单最底下——避免「翻半天找不到删除」或「误触保存旁边的删除」。

### 表单分组微调建议
- 把「**一句话简介**」从「基本信息」里拆出来，和「**经验履历**」合并成一组「**对外展示**」。因为这两者**都直接出现在名片上**，用户改的时候会立刻在左侧预览看到效果，认知闭环最短。
- 「**信任级**」不要放在弹窗底部角落里（现状是 modal footer 一个 badge），建议在表单最下方独立一组「**系统信息**」，把 trust、version、id 只读展示——这是「给用户看」的，不是「让用户改」的。

## 三、Q2 「继承自」标签

### 业务含义先对齐

从 `profile.ts` + `compile.ts` 看：

> `baseMode` 是 **corum profile 继承官方 dsh 四种 preset（standard / ptc / minimal / cordis）的 persona**。编译时 `BASE_MODE_PERSONA[baseMode]` + 用户自定义 prompt 拼接。

所以「继承自」= **「这个 Agent 的性格底色来自哪个官方基础模式」**。是**人格的师承**，不是能力的来源（能力在技能 / MCP / 终端组里）。

### 建议：在名片上**默认不显示**，hover / 二级页面才显示

理由：
1. **名片正面信息已经很挤**：头像 / 昵称 / 信任级徽标 / 岗位 / 擅长 / 经验 / 模型行 / 维度 chip / chevron —— 9 个元素。再加一个「继承自 standard」chip，新手会分不清「岗位维度」和「继承自」的区别（都是 chip，都是一行字）。
2. **对新手是噪音**：一个刚开始用的用户，根本不关心 standard 和 cordis 的区别，他关心的是「这货是研发还是产品」。
3. **对老手有用但低频**：老手关心继承自，是在**调 prompt 调不出感觉**、或者**对比多个 Agent 微调差异**时。这两个场景都发生在二级页面，不在主页。

### 具体方案

| 位置 | 是否展示 | 形式 |
|---|---|---|
| 主页名片正面 | ❌ 不展示 | — |
| 主页名片 hover 浮层（或长按 / ⌘-hover） | ✅ 展示 | 「继承自 standard · 默认编码 Agent」一行小字 |
| 二级编辑页 · 表单内 | ✅ 重点展示 | 改为「**继承自**」字段（下拉 4 选项），下方紧跟一条**只读提示**：「将继承 standard 的系统提示词与 persona」 |
| 二级编辑页 · 左侧名片预览 | ✅ 展示 | 名片下方加一行小字 `继承自 standard`，弱化样式（`$label-dimmed`，11px） |

### 文案建议

把字段名从「官方 Agent 模式」改成「**继承自**」，但**选项文案**保留信息量：

- `standard` → **标准**（功能完整的编码 Agent）
- `ptc` → **PTC**（标准 + Code Mode 多步）
- `minimal` → **极简**（仅 bash + 编辑器）
- `cordis` → **创造**（用于创建自定义 preset）

> 关键：字段叫「继承自」，选项里**不要重复「继承自」三个字**。标签上写「继承自 standard」就够了。

## 四、Q3 提示词放大编辑

### 先想清使用频率

从 `profile.ts` 看，prompt 是「**叠加在 baseMode persona 之上**」的一段用户自定义文本。真实使用场景：

| 用户 | 频率 | 场景 |
|---|---|---|
| 新手 | **极低**（建一次不再改） | 复制别人的 prompt 模板进来 |
| 进阶 | **中等**（每周 1-2 次） | 跑出来的效果不对，回来调 prompt |
| 老手 | **高频**（每天多次） | 微调措辞、试不同 persona、A/B 两版对比 |

结论：**放大编辑不是「大众高频」功能，但是「老手刚需」**。设计上应该「**默认藏好，需要时一键到位**」，不要默认放大。

### 建议方案

**默认态（表单内）**：
- textarea 3 行，右侧角标一个 `Maximize2` 图标（Lucide），tooltip「放大编辑」
- 旁边紧跟 `Sparkles` AI 润色按钮（**不要 disabled「即将上线」**，要么不做入口，要么做真的——见下方红线）

**放大态**：
- 弹出一个**遮罩 + 大文本框**（占满右侧表单区域，约 80% 宽度，高度约 60vh），而不是「把整个右侧占满」——保留左侧名片预览可见，用户调 prompt 时能**实时看到首行变化反映到「擅长什么」上**
- 右上角三个按钮：`Sparkles AI 润色` / `Minimize2 缩小` / `保存`
- **保存行为**：点保存 → 写回 draft → **自动缩小回表单**。不要在放大态里再开一个「保存并继续编辑」的分支，复杂度不值。
- **AI 润色行为**：
  - 在放大态内联进行，润色结果**直接替换 textarea 内容**，但**保留撤销**（Ctrl+Z 回退到润色前）
  - 润色按钮置灰 + loading，期间禁止再次点击
  - 润色失败 toast 提示，不清空用户原文

### 红线

> 现状代码里 `AI 润色` 按钮是 `disabled title="即将上线"` —— **如果这一版不做，就直接去掉这个按钮**，不要保留一个 disabled 的占位。disabled 的「即将上线」按钮是产品大忌：它既暗示了功能存在，又告诉用户「我们用不了」，双重负面。

## 五、Q4 完整状态链路图

### 主链路（Happy Path）

```
[名片主页]
   │  点击名片
   ▼
[二级编辑页]
   │  改字段 → 左侧预览实时联动
   ├─→ 点「放大」→ [提示词放大态] → 保存/缩小 → 回编辑页
   ├─→ 点「+ 添加技能」→ [技能绑定弹窗] → 确认 → 回编辑页
   ├─→ 点「+ 添加 MCP」→ [MCP 绑定弹窗] → 确认 → 回编辑页
   │
   ├─→ 点「保存」→ 校验
   │     ├─ 失败 → 顶部 error 提示（id 非法 / 为空），留在编辑页
   │     └─ 成功 → 回主页 + toast「已保存」+ 名片数据刷新
   │
   └─→ 点「删除」→ [删除确认弹窗]
         ├─ 取消 → 回编辑页
         └─ 确认 → 回主页 + toast「已删除」+ 名片移除
```

### 新建链路

```
[名片主页]
   │  点「+ 新建预设」
   ▼
[二级编辑页 · 新建态]
   │  - 预设 ID 可编辑（编辑态为只读）
   │  - 信任级默认 'user'，不可改
   │  - 无「删除」按钮
   ▼
点「创建」→ 校验 → 成功回主页（新卡片出现在网格末尾）
```

### 需要补的边界态（产品必须给开发讲清楚）

| 场景 | 期望行为 |
|---|---|
| 编辑页有未保存修改，点「返回」 | **弹确认**：「有未保存修改，确定离开？」不要默默丢失 |
| 编辑页有未保存修改，点「删除」 | 删除流程独立于未保存修改，删的是**磁盘上的版本**，删完回主页 |
| 提示词放大态，点遮罩 / Esc | **不保存**缩回表单（保留 draft 中已有内容） |
| 技能 / MCP 弹窗，点遮罩 | 取消，不写入 draft |
| 保存中网络异常 | error 显示在表单顶部，**不清空表单** |
| 新建时 ID 与已有冲突 | 前端预校验 + 后端二次校验，错误提示「该 ID 已存在」 |
| 删除一个正在被任务引用的 Agent | 后端需要拒绝并提示「该 Agent 正被 N 个任务使用」（这是 **后端契约**，前端不背锅） |

### 弹窗层级（z-index 从低到高）

```
二级编辑页  <  技能绑定 / MCP 绑定  <  提示词放大态  <  删除确认  <  toast
```

> 提示词放大态的 z-index 要**高于**技能 / MCP 弹窗——因为用户可能在绑定技能弹窗里需要参考 prompt 内容，此时从放大态「预览」是合理的。

## 六、给开发的「一句话需求清单」

按优先级排序，可直接转成 issue：

1. **P0** 二级页面改为左预览（sticky 320px）/ 右表单双栏，预览实时联动
2. **P0** 「官方 Agent 模式」字段重命名为「**继承自**」，主页名片**不显示**，二级页预览和表单内显示
3. **P0** 编辑页未保存修改时，返回需弹确认
4. **P1** 提示词放大态：保留左侧预览可见，保存自动缩回，AI 润色支持撤销
5. **P1** 删除按钮挪到编辑页顶部工具条右侧，独立确认弹窗
6. **P1** AI 润色按钮：要么做真的，要么下线，**不留 disabled 占位**
7. **P2** 名片 hover 浮层展示「继承自 xxx」一行小字
8. **P2** 后端补充「删除被引用 Agent」的拒绝逻辑

## 七、一句话总结

> **把 Agent 当人来设计**：主页是「人才市场」，名片是「简历」，二级页是「面谈现场」，提示词是「脾气秉性」，继承自是「师承出处」。所有交互优先级、信息密度、放大/收起，都从「我作为用人方，想多快、多准地认识并信任这个 Agent」出发倒推。
